## Name

`verdictpack` — coined compound ("verdict" = the measured judgement
each skill in the pack exists to produce; "pack" = the skill-pack
format). Collision checks run 2026-11-16:

- GitHub repository search `verdictpack in:name`: **0 repositories**.
- PyPI `verdictpack`: **not registered** (project JSON returns 404).
- Web search for the exact name: **no product, company, or tool**
  uses it. The nearest names found are in different fields and share
  at most one word (`benchverdict`, a performance-measurement
  validity library; `veridict`, a Rust evaluation gate) — no
  branding, copy, or assets of any third party are used.

Candidates checked and rejected in the same pass: `provepack`
(GitHub-clear, but a one-step neighbour of `proofpack`, which is
crowded in the adjacent evidence niche — a PyPI product, an MCP
server, and multiple projects); `benchprove` (GitHub-clear, but a
transposition neighbour of `proofbench`, an eval harness for agent
skills on PyPI — the identical niche); `probepack` (a named product
angle in an LLM-monitoring project, plus 38 `probe-pack` repos);
`assaypack` / `goldassay` / `verdictkit` / `gaugepack` (exact-name
GitHub repositories exist); `truelabel` (28 repos) and `scalecheck`
(18 repos) — taken; `proveground` (clear but unpronounceable as a
brand).

Portfolio check: the pack is the method layer of the author's
evalcrucible (grader validation) and runreckon (run scoring) — it
teaches and operationalises their procedures in skill form and
links to both. It duplicates neither tool's function: the tools
execute at scale; the pack instructs an agent or a human through
one application of the method.

## Originality

All copy, code, templates, and examples in this repository were
authored for it. The subject matter is the author's own published
methodology: grader validation under a pre-registered acceptance
bound and the four-probe benchmark audit (from evalcrucible);
eight-dimension run scoring, policy-as-code gating, fault-injection
scorer validation, and measured judge calibration (from runreckon);
and the author's validation protocol distilled from a real
benchmark review failure (domain-first acceptance questions,
near-miss negative tests, qualifier preservation, conversation set
operations, never trusting the system's own classification as the
verification signal).

The skill-pack *format* (a folder per skill, `SKILL.md` with
name/description frontmatter) is the standard agent-skill format
used across the ecosystem; per the portfolio's reference rule, only
the format idea was taken from the format's leaders — no skill
text, structure, naming, or content from any existing pack is used.
Every worked example is synthetic and original, and every number in
an example is reproduced by the bundled scripts.

A sixth skill, `layer-your-eval-program`, was added 2026-11-16
after an audit of this pack against a published practitioner
doctrine of LLM evaluation (Hamel Husain, "Your AI Product Needs
Evals", 2024 — forwarded to the author as a summary with the source
link). Per the same reference rule, only the *practices* were
taken: cost-layered evaluation cadence, synthetic test-input
generation, the pass rate as an explicit product decision, and
per-class precision/recall reporting (the last also added to
evalcrucible and to this pack's two measurement scripts in the same
pass). All prose, examples, and code written for the addition are
original to this repository.
